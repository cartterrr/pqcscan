# pqcscan

Небольшой сканер, который ищет в коде и на TLS-серверах криптографию, уязвимую
для квантового компьютера (RSA, ECDSA, ECDH, X25519, Ed25519, DH, DSA), и по
результатам собирает примерный план миграции.

Смотрит исходники, конфиги, ключи и сертификаты, файлы зависимостей. Выводит
сводку в терминал, а при желании ещё JSON, Markdown, SARIF (для GitHub code
scanning) и CBOM в формате CycloneDX 1.6. Всё работает локально, никуда ничего
не отправляется.

English: [README.md](README.md).

## Зачем это

Алгоритм Шора на достаточно большом квантовом компьютере ломает RSA и
криптографию на эллиптических кривых. Такого компьютера пока нет, но трафик,
записанный сегодня, можно будет расшифровать, когда он появится. Поэтому обмен
ключами стоит проверять уже сейчас. С подписями спешки меньше: чтобы подделать
подпись, квантовый компьютер нужен в момент атаки.

Замену NIST стандартизировал в 2024 году: ML-KEM (FIPS 203) для обмена
ключами, ML-DSA (FIPS 204) и SLH-DSA (FIPS 205) для подписей. Сроки, на которые
сейчас ориентируются:

| Источник | Когда | Что |
|---|---|---|
| NIST IR 8547 (финальная версия, октябрь 2026) | после 2030 | RSA, ECDSA, EdDSA, (EC)DH устаревают при любой длине ключа |
| NIST IR 8547 | после 2035 | запрещены |
| NCSC (Великобритания) | 2028 / 2031 / 2035 | инвентаризация / важные системы / всё |
| ЕС | конец 2026 / 2030 / 2035 | первые шаги / системы высокого риска / полный переход |

Все эти планы начинаются с инвентаризации. С ней сканер и помогает.

## Установка и запуск

```bash
git clone https://github.com/cartterrr/pqcscan
cd pqcscan
pip install -e .

pqcscan scan путь/к/проекту                    # папка, файл или .zip
pqcscan scan . --out-dir pqc-reports            # JSON, SARIF, CBOM и Markdown разом
pqcscan scan . --fail-on high                   # код выхода 1, если есть high
pqcscan tls example.com api.example.com:8443
pqcscan rules                                   # список правил
```

Нужен Python 3.10+. Зависимости: `click` и `cryptography`.

`--fail-on` не учитывает тесты и совпадения в комментариях, чтобы CI не падал
из-за теста, который генерирует RSA-ключ. Строку, которую уже проверили,
можно скрыть комментарием `pqcscan:ignore`.

`pqcscan tls` запускайте только против своих серверов или тех, которые вам
разрешили тестировать.

## Что проверяется

Код на Python, JS/TS, Go, Java/Kotlin, C#, C/C++ и Rust: 70 правил на
регулярных выражениях, каждое привязано к конкретному вызову библиотеки.
Вызовы, разбитые на несколько строк, тоже находятся.

Конфиги: TLS 1.0/1.1 и слабые шифры в nginx и Apache, RSA- и DSA-ключи в
настройках SSH.

Ключи и сертификаты: алгоритм, длина, срок действия. Если сертификат действует
дольше 2035 года, он получает high. Приватные ключи попадают в отчёт, но их
содержимое не выводится нигде. Большие CA-бандлы сворачиваются в одну строку.

Зависимости: какие криптобиблиотеки подключены, включая постквантовые (liboqs,
CIRCL, `@noble/post-quantum`, Bouncy Castle PQC).

Уже существующий постквантовый код (ML-KEM, ML-DSA, SLH-DSA, `X25519MLKEM768`)
сканер тоже замечает и помечает как info. То, что ML-KEM есть в коде, ещё не
значит, что он используется правильно.

### Как проверяется гибридный TLS

Модуль `ssl` в Python не сообщает, какая группа обмена ключами была выбрана.
Поэтому сканер вручную собирает TLS 1.3 ClientHello, где перечислены только
гибридные группы (`X25519MLKEM768` = `0x11EC` и ещё три), а ключевой доли нет
совсем. Сервер, который поддерживает такую группу, отвечает HelloRetryRequest
с её номером. Сервер, который не поддерживает, отвечает алертом
`handshake_failure`. Клиенту не нужно считать ML-KEM, так что проверка
работает на любой версии Python и OpenSSL. Код лежит в
[src/pqcscan/tls.py](src/pqcscan/tls.py).

## Ограничения

Правила находят вызовы API, но не отслеживают, куда дальше идут данные.
Каждую находку должен посмотреть человек, а пустой отчёт не означает, что
система готова к квантовым компьютерам. Бинарники, контейнеры, HSM, облачные
KMS, сторонние сервисы и криптография, которая выбирается из конфига во время
работы, в проверку не попадают.
